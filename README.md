# «Вместе» — совместный просмотр видео

Вставляете ссылку (YouTube, Google Drive, `.mp4`, `.m3u8`) → получаете комнату → друзья по ссылке смотрят синхронно, видят позицию каждого зрителя на общей шкале, болтают в чате и кидают реакции. Без регистрации.

```bash
npm install
npm run dev            # сервер :3001 + клиент :5173 (Vite проксирует /api и /socket.io)
# продакшен
npm run build && npm start   # один процесс на :3001 раздаёт и API, и собранный клиент
```

Откройте http://localhost:5173, создайте комнату, откройте ссылку во второй вкладке/на телефоне (Vite слушает LAN: `http://<ip-компьютера>:5173`).

## 1. Архитектура

```
┌──────────────── Браузер (React + Vite) ────────────────┐        ┌──────────── Node.js ────────────┐
│ Home ─► RoomPage                                       │        │ Express                          │
│           ├─ VideoStage                                │  REST  │  GET /api/rooms/:id (пароль?)    │
│           │   ├─ PlayerAdapter ── Html5 (+hls.js)      │◄──────►│  static client/dist (prod)       │
│           │   │                └─ YouTube IFrame API   │        │                                  │
│           │   ├─ useSync  ◄── ядро синхронизации       │   WS   │ Socket.io                        │
│           │   ├─ ProgressBar (маркеры зрителей)        │◄──────►│  RoomStore (in-memory → Redis)   │
│           │   ├─ субтитры / ReactionLayer              │        │   Room: state, members, chat,    │
│           ├─ ViewersPanel                              │        │         subtitles, hostId        │
│           └─ Chat                                      │        │  батч-рассылка зрителей 1 раз/с  │
│ ServerClock (NTP-синхронизация часов)                  │        │  сборщик пустых комнат (10 мин)  │
└────────────────────────────────────────────────────────┘        └──────────────────────────────────┘
```

**Принципы**

1. **Хост — единственный источник истины.** Только он шлёт `host:state {playing, position, rate}`. Сервер проверяет права, ставит **серверную** метку `updatedAt`, увеличивает `seq` и рассылает всем.
2. **Состояние, а не события.** Клиенты получают не «нажали паузу», а полный снимок `PlaybackState`. Пропущенное сообщение не ломает синхронизацию — следующее его исправит. Новичок получает снимок при входе.
3. **Позиция вычисляется, а не пересылается каждую секунду:** `expected = position + (serverNow − updatedAt) × rate`. Трафик минимальный, а все клиенты «тикают» одинаково.
4. **Общее время.** `ServerClock` делает серию пингов и берёт замер с минимальным RTT: `offset = serverNow − (t0 + rtt/2)`. Точность обычно 5–30 мс. Пересинхронизация раз в 30 с.
5. **Свои контролы.** Нативные контролы `<video>` и YouTube отключены, поверх iframe — прозрачный `click-shield`. Поэтому любое действие — это явная команда из UI, а не событие плеера, и нет «эха» (когда программный seek воспринимается как действие пользователя и улетает остальным).
6. **Единый `PlayerAdapter`.** Синхронизация не знает, YouTube это или mp4. Новый источник = новый адаптер.

### Протокол (`shared/protocol.ts`)

| Клиент → сервер | Назначение |
|---|---|
| `time:ping(t, ack)` | синхронизация часов |
| `room:create({name, password?, source}, ack)` | создать комнату → `roomId` |
| `room:join({roomId, clientId, nickname, password?}, ack)` | войти → полный `RoomSnapshot` |
| `host:state({playing, position, rate})` | команда хоста + heartbeat раз в 4 с |
| `host:transfer(viewerId)` / `host:source(source)` | передать хоста / сменить видео |
| `viewer:report({position, status})` | отчёт зрителя раз в 1 с |
| `chat:send(text)` / `chat:react(emoji)` / `subs:set({name,text})` | чат, реакции, субтитры |

| Сервер → клиенты | |
|---|---|
| `state` | новый `PlaybackState` |
| `viewers(list, hostId)` | список зрителей со статусами — **батчем не чаще 1 раза/с** |
| `chat`, `reaction`, `source`, `subs` | соответствующие обновления |

Статус зрителя (`смотрит / пауза / загрузка / отстаёт / впереди / офлайн`) считается **на сервере** по отчёту и ожидаемой позиции комнаты; порог «отстаёт/впереди» — 3 с (`DRIFT_STATUS_THRESHOLD`).

**Идентичность.** `clientId` хранится в `sessionStorage` вкладки: перезагрузка страницы и обрыв сети не теряют место и роль хоста. Отключившийся участник держится 30 с, потом удаляется, а хост переходит к самому «старому» онлайн-участнику.

## 3. Логика синхронизации (`client/src/sync/useSync.ts`)

Зритель каждые **250 мс**:

```ts
const expected = s.playing ? s.position + (clock.now() - s.updatedAt) / 1000 * s.rate : s.position;

if (s.playing && player.isPaused()) player.play();      // догоняем play/pause
if (!s.playing && !player.isPaused()) player.pause();
if (player.isBuffering()) return;                       // во время буферизации не дёргаем

const drift = player.getTime() - expected;
if (|drift| > 1.0 c (YouTube: 1.5 c))  → seek(expected + упреждение), затем 1.5 с «тишины»
else if (|drift| > 0.08 c && плеер умеет дробную скорость)
                                       → rate = s.rate × (1 − clamp(drift·0.25, ±0.1))   // 0.9×…1.1×
else                                   → rate = s.rate
```

* **Мягкая подстройка скоростью** вместо постоянных перемоток: рассинхрон до секунды исчезает за несколько секунд незаметно для глаза (питч сохраняется браузером).
* **Упреждение при seek** (0.15 с для `<video>`, 0.4 с для YouTube) компенсирует время самой перемотки.
* **Кулдаун 1.5 с** после seek защищает от «пилы» перемоток на медленной сети.
* **Heartbeat хоста** раз в 4 с исправляет накопившийся дрейф (буферизация хоста, неточный `rate`). Если хост буферизуется, heartbeat не шлётся.
* Команда хоста применяется у него **локально сразу** (optimistic), а затем рассылается.

## 4. Возможные проблемы и решения

| Проблема | Что сделано / что делать |
|---|---|
| **Автоплей.** Браузеры не дают запустить видео со звуком без жеста пользователя | Экран «Войти в зал»: клик = жест, после него `play()` разрешён. Если всё равно заблокировано — играем без звука и показываем кнопку «включить звук» |
| **CORS для mp4** | `<video src>` CORS не требует — работает с любым сервером. Не ставьте `crossOrigin`, иначе сломаются источники без заголовков |
| **CORS для HLS** | hls.js качает сегменты через XHR → сервер потока **обязан** отдавать `Access-Control-Allow-Origin`. Иначе — свой прокси (см. ниже) или Safari (нативный HLS) |
| **Google Drive** | Ссылка превращается в `drive.usercontent.google.com/download?...&confirm=t`. Файл должен быть доступен «всем по ссылке». Для больших файлов Google режет квоты/просит подтверждение — надёжнее перезалить на S3/R2/Backblaze. Встроенный плеер Drive (`/preview`) управлять из JS нельзя |
| **YouTube** | Только IFrame API: дискретные скорости, seek ≈ 0.3–1 с, нельзя менять скорость плавно → только жёсткие перемотки с порогом 1.5 с. Некоторые видео запрещают встраивание (ошибки 101/150) — показываем понятное сообщение. Встроенные субтитры YouTube недоступны API — свои .srt работают |
| **Кодеки** | MKV/HEVC/AC3 браузеры обычно не играют. Нужен mp4 (H.264+AAC), webm или HLS |
| **Сетевые задержки** | Серверное время + вычисляемая позиция делают задержку доставки неважной; точность ~±0.1 с для mp4 |
| **Мобильные** | `playsinline` (iOS не уходит в системный плеер), свой «псевдо-фулскрин» для iOS Safari, вкладки «Чат/Зрители». На iOS громкость регулируется только кнопками телефона |
| **Фоновые вкладки** | Таймеры в скрытой вкладке замедляются до 1 Гц — синхронизация продолжает работать, но грубее; при возвращении догоняется за тик |
| **Кодировка .srt** | Читаем UTF-8, при «кракозябрах» — автоматически windows-1251. Сдвиг субтитров ±0.5 с — локально у каждого |

## 5. Продакшен и масштабирование

* **Один инстанс** (до нескольких тысяч одновременных зрителей): `npm run build && npm start`, за nginx/Caddy с HTTPS и поддержкой WebSocket (`proxy_set_header Upgrade $http_upgrade; Connection "upgrade"`).
* **Несколько инстансов:** 
  1. `@socket.io/redis-adapter` — рассылка `io.to(room)` между нодами; 
  2. `Room` хранить в Redis (hash `room:{id}`: state, hostId, source; list `room:{id}:chat` с `LTRIM 200`; TTL 10 мин при пустой комнате); 
  3. либо проще — sticky routing по `roomId` (все участники комнаты на одной ноде), тогда достаточно адаптера.
* **Безопасность:** пароль хранится как SHA-256 и сравнивается `timingSafeEqual`; все входящие события валидируются; права хоста проверяются на сервере; анти-флуд 5 сообщений / 3 с; ограничение размера субтитров 600 КБ. Для публичного запуска добавьте rate-limit на создание комнат по IP и `helmet`.
* **CORS сервера:** переменная `CORS_ORIGIN=https://site.ru` (по умолчанию разрешено всё). Если клиент на другом домене — соберите его с `VITE_SERVER_URL=https://api.site.ru`.
* **Прокси для HLS без CORS** (по желанию): маршрут `GET /proxy?u=...`, который стримит ответ и добавляет `Access-Control-Allow-Origin` + переписывает ссылки в `.m3u8`. Обязательно белый список доменов, иначе получится открытый прокси.
